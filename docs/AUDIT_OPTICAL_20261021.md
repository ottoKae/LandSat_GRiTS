# Landsat、S2 与 Resolver 审查记录（2026-10-21）

> 执行更新：本文保留修复前的审查及设计记录。随后已修复下列 10 项问题，并实现同瓦片日合成；Resolver 已更新为 0.3.0。当前行为、测试和边界以 [执行验收报告](../../GRiTS-Resolver/docs/DAILY_VALIDATION_20261021.md) 为准。

本组仓库分别负责 Landsat 格网归档、Sentinel-2 原生分辨率归档，以及跨数据集的空间和时间读取。本次按 ponytail-audit 检查正确性、数据保全、失败处理和集成边界；假设单用户批量处理、多个下载线程、每个归档单写入者，读取已停止写入的数据。

**结论：Landsat 未发现阻塞性新缺陷；S2 的续写保护和 Resolver 的空间读取仍有必须修复的问题。Resolver 尚未接入本轮新增的光学单景接口。用户已明确需要“同一 MGRS 瓦片内，同日多景合成”：这是合理的派生产品，日期可作为合成分组字段，但不能代替原始场景或采集身份。**

本次只新增诊断、结果和报告，没有修改生产代码或深圳归档。已有未提交改动原样保留。以下 10 项都有具体复现，不把已声明的单写入限制、历史插入限制等算作缺陷。

## 必须修复

### 1. S2 提交记录缺失时，续写会截断原有影像

- 位置：[zarr_writer.py](../../S2-GRiTS/src/s2grits/zarr_writer.py)，`_load_metadata()` 第 67–74 行、续写第 689–690 行。
- 行为：writer 通过 JSON 提交记录判断已经完成的场景数；新旧两种记录都不存在时返回空列表。
- 复现：合成归档已有 `scene-a`、`scene-b`，移走提交 JSON 后写入 `scene-c`。操作成功，但原数组先缩至 0，最终只剩 `scene-c`。
- 最小修复：已有非空 Zarr 数组但没有可用提交记录时，在任何修改前拒绝续写，要求恢复记录。不能将这种状态当作新库。
- 不修复的后果：不完整复制、误删 sidecar 后的一次正常续传就可能删除仍可恢复的影像数据。

### 2. S2 续写时改变波段配置会破坏共同时间轴

- 位置：[zarr_writer.py](../../S2-GRiTS/src/s2grits/zarr_writer.py) 第 537、643、652 行；[audit.py](../../S2-GRiTS/src/s2grits/audit.py) 第 58 行。
- 行为：resize 和审计只遍历本次配置的波段，未先核对归档原有的完整波段契约。
- 复现：第一景保存 `blue+green`，第二景只配置 `blue`。写入成功后，`time/blue` 长度为 2，`green` 长度为 1；新 reader 拒绝整库，而按本次 blue 配置运行的审计没有警告。
- 最小修复：固定归档的波段及分辨率组，在任何写入前校验一致；审计遍历完整归档契约。补充质量变量需显式迁移或独立伴随库。
- 不修复的后果：一次配置调整就能让长期归档不可读，并被现有审计漏报。

### 3. Resolver 同一像元的插值结果随读取窗口大小变化

- 位置：[spatial.py](../../GRiTS-Resolver/src/grits_resolver/spatial.py) 第 42–56、97–106 行。
- 行为：仅截取目标范围覆盖的源像元，未保留双线性插值所需邻域。
- 复现：深圳 49QHE、R032 的 `nir_narrow` 从 20 m 对齐到 30 m；同一目标像元 `(157,45)` 在 32×32 窗口中为 **4012.357910 DN**，单独读取 1×1 为 **4074.015625 DN**，相差 **61.657715 DN**。
- 最小修复：根据插值核和缩放比例扩展源窗口，裁剪至实际源边界；验证整窗与分块读取一致。任意分辨率比下不能只假设固定扩一像元就足够。
- 不修复的后果：点提取、分块推理和整图处理产生不同结果，空间接边可能出现接缝。

### 4. Resolver 便捷接口隐式选择第一条轨道或存储

- 位置：[resolver.py](../../GRiTS-Resolver/src/grits_resolver/resolver.py) 第 152–176、191、215 行。
- 行为：`s1_entry()`、`s2_entry()` 使用 `matches[0]`；高层时间匹配和空间读取继续使用这个结果。
- 复现：反转两条目录记录的顺序，默认选择从 S1 18/S2 32 改为 S1 91/S2 132。真实深圳单库中，返回的条目元数据是 R132，但 `s2_time_index=1` 实际读取 R032。
- 最小修复：显式选择源场景及目标轨道；多个独立存储或轨道存在歧义时拒绝默认选择。场景 ID、索引、时间和轨道必须来自同一提交记录；同一存储的多行目录不能简单视为多个存储。
- 不修复的后果：生产端已经保留的单景身份在读取层丢失，目录顺序改变就可能换轨或遗漏数据。

### 5. S2 工作流报告失败，CLI 仍正常退出

- 位置：[cli.py](../../S2-GRiTS/src/s2grits/cli.py) 第 88–90、145 行；[workflow.py](../../S2-GRiTS/src/s2grits/workflow.py) 第 551–570 行。
- 行为：命令只打印工作流结果，不把失败状态转换为非零退出码。
- 复现：向真实 CLI 入口注入工作流返回值 `audit_report.ok=False`、瓦片 `status=failed`，`cli.main()` 正常返回 `None`。工作流本身确实存在返回这类结果而不抛异常的路径。
- 最小修复：保留结果 JSON，审计失败或瓦片 `failed/partial` 时返回非零退出码。
- 不修复的后果：定时任务和批处理会将不完整下载当作成功。

### 6. S1 两轨无共同月份时，Resolver 崩溃

- 位置：[s1.py](../../GRiTS-Resolver/src/grits_resolver/s1.py) 第 243–246 行。
- 行为：`read_common_pair()` 用共同月份构造 NumPy 索引。
- 复现：一轨只有 2024-01，另一轨只有 2024-02；空列表变为浮点索引，触发 `IndexError`。
- 最小修复：明确使用 `dtype=np.intp`，定义并返回空的共同时间维，增加无交集测试。
- 不修复的后果：正常的缺测组合使整个批次失败。

## 应修复

### 7. Resolver 请求 SCL 会切换其他变量的解码方式

- 位置：[spatial.py](../../GRiTS-Resolver/src/grits_resolver/spatial.py) 第 31–34、78 行。
- 行为：变量列表含 `scl` 时，整个组按原始值读取；否则交给 xarray 默认缩放和缺测解码。
- 复现：含 CF `scale_factor/add_offset/_FillValue` 的合成 Zarr，单读 red 得 `-0.0876889`，读 red+SCL 得 `123.111`；云概率零值单读为 NaN，与 SCL 同读保留 0。
- 最小修复：明确统一数值约定，按变量处理缩放及缺测，保证单变量和批量读取一致。
- 不修复的后果：兼容格式或历史库可能因多请求一个变量而改变单位和有效像元。**当前深圳库使用 `scale/offset` 且没有 `_FillValue`，未触发此问题**；校园 1024 个覆盖像元中的 949 个云概率零值在两种读取下均保留。

### 8. Resolver 用唯一 UTC 代替场景身份，拒绝合法重复时间

- 位置：[resolver.py](../../GRiTS-Resolver/src/grits_resolver/resolver.py) 第 139 行；独立质量配对路径 [s2_quality.py](../../GRiTS-Resolver/src/grits_resolver/s2_quality.py) 第 105 行。
- 行为：目录验收对时间去重，质量伴随读取也限制唯一 UTC。
- 复现：两个不同 item 拥有同一 UTC，新 S2 生产端保存两条观测，Resolver 却得到 `catalog=1 zarr=2` 而拒绝打开。
- 最小修复：使用 collection/item 和提交顺序核对身份，时间只是校验字段；独立质量配对索引一并迁移。
- 不修复的后果：生产端通过验收的数据不能保证被 Resolver 读取。当前表现为显式报错，没有静默合并。

### 9. S2 下载缓存未绑定稳定来源

- 位置：[zarr_writer.py](../../S2-GRiTS/src/s2grits/zarr_writer.py) 第 249–266 行。
- 行为：缓存以 item/band 命名，只要 TIFF 可打开就复用。
- 复现：同一 item/band 已有旧 TIFF，传入另一个稳定资产地址，仍返回旧文件，不请求新来源。
- 最小修复：缓存收据绑定 collection/item/asset 和规范化的稳定来源；上游提供大小或校验和时核对。排除临时签名参数差异，来源内容改变时拒绝静默复用。
- 不修复的后果：同 ID 的资产被修订后可能继续读取旧数据。**没有证据表明深圳缓存错误**；深圳逐文件 SHA-256 验收是独立验收脚本的能力，不能等同于普通下载器已有此校验。

### 10. Landsat 搜索忽略同 ID 的冲突来源

- 位置：[catalog.py](../src/landsat_grits/catalog.py) 第 311–315 行。
- 行为：分页结果按 `collection/id` 去重，保留首条。
- 复现：两个分页条目的 ID 相同、green 的稳定资产地址不同，来源指纹不同，但搜索仍保留首条；交换分页顺序会改变结果。
- 最小修复：重复 ID 时比较已有 `scene_fingerprint`，稳定来源不同则抛出 `CatalogError`；仅临时签名变化可以正常去重。
- 不修复的后果：上游在搜索期间修订资产时，冻结结果依赖分页顺序。当前真实试验未出现冲突；归档续传层已正确拒绝同 ID 来源变更。

## “同天合并”是否合理

用户确认的用途是 **同一 MGRS 瓦片内，同日多景合成**。本次设计重点是将同瓦片的候选场景对齐到共同目标格网后，生成每天一幅的结果；跨瓦片空间拼接另行区分。

**合理的空间拼接单位应是同一次采集；日合成则是另一种明确的派生产品。** 日期可用于检索和分桶，不能单独证明同一轨道、同一卫星或同一次过境。相邻瓦片的精确时间可能有差别，直接要求时间戳完全相同也不合适。

| 场景 | 建议 |
|---|---|
| S2 同次过境的相邻 MGRS 瓦片 | 按卫星 + datatake 起始时间 + 绝对轨道分组，再做空间拼接 |
| Landsat 同卫星、同 WRS 系统及 Path、同次过境的相邻 Row | 可以拼接；Row 是沿轨景框，不是另一条轨道 |
| 同一 Landsat 场景被切入相邻 MGRS 瓦片 | 用原始 collection/scene_id 识别同一来源，拼接时避免重叠计数 |
| 同一天但不同轨道、卫星或过境 | 保留独立观测；如需每日一幅，显式生成日合成，并保存来源与实际时间 |
| 不同产品级别、传感器或不兼容处理版本 | 不直接混成一张原生影像；先确定物理量、波段对应和版本处理规则 |

这与官方产品组织相符：S2 的 datatake 表示连续采集，产品瓦片带有空间重叠；[Copernicus 产品说明](https://sentiwiki.copernicus.eu/web/s2-products)。USGS Collection 2 ARD 也允许某天的一个 tile 由同一 WRS-2 Path 的 1–3 景构成，说明“同天且同轨”的拼接具有实际先例；其格网是 Albers ARD，不能直接等同本项目 MGRS：[USGS C2 ARD](https://www.usgs.gov/landsat-missions/landsat-collection-2-us-analysis-ready-data)。

适合本仓库的最小设计：

1. 原始 Zarr 继续按传感器、产品级别和场景保留，不覆盖原始时间轴。
2. 在 Resolver 增加显式采集拼接读取：先选场景、再按采集身份归组、最后投到同一目标格网。
3. 同一像元用于分析的全部波段及对应质量信息来自同一来源景；输出 `source_index`、来源 ID 表、有效掩膜及实际采集时间。有效覆盖与无云筛选分别处理。
4. 重处理版本先去重；重叠瓦片只计一次观测。拼接优先级固定并记录，不能靠目录顺序决定。
5. 若增加日合成，明确 UTC 或业务时区、选择规则和产品名称；不同过境可参与，但不能冒充单次采集。

现有 `first_valid_mosaic()` 已保证一像元的全部波段取同一来源，并返回来源索引和重叠数；它只接收数组，调用者仍需核对采集身份。当前没有自动“按日期合并全部场景”的生产路径。

深圳两条 S2 轨道分别为 2024-11-26/R132、2024-11-29/R032。此前验收证明它们保持独立、没有跨景填补，**尚未验收同次采集的跨瓦片拼接或同日跨轨日合成**。

### 已确认用途：同瓦片日合成

建议保留两种读取结果：原始单景读取用于追溯和观测几何研究；日合成读取用于每天一幅的分析。日合成可作为 Resolver 的派生视图，按需导出独立 Zarr，无需替换原始归档。

| 规则 | 建议设计 |
|---|---|
| 分组 | MGRS 瓦片 + 传感器/产品级别 + 兼容物理量与波段 + 目标格网 + 日期；默认采用 UTC 日并记录时区 |
| 同日跨轨 | 可以参与日合成；保留各景轨道、实际时间和来源，输出标为多景合成 |
| 跨卫星 | 单独声明产品规则；同属一个传感器家族不代表波段响应或定标完全相同 |
| 重复产品 | 同一采集的重处理版本先按固定版本规则去重，再参与质量比较 |
| 选取来源 | 逐像元筛选有效、通过质量规则的候选；质量相同按固定的来源优先级和场景 ID 决定，记录规则版本 |
| 波段一致性 | 同一目标像元实际参与分析的各波段及对应 QA 来自同一景；不能逐波段分别选最佳景 |
| 无合格来源 | 保持无效，不借其他日期填补；缺少可靠质量信息时明确标注，不能把有效覆盖等同于无云 |
| 溯源 | 保存逐像元 `source_index` 及来源表；表内含 scene/item ID、卫星、轨道、精确 UTC 和处理版本，因而能恢复每个像元的实际观测时间 |
| 时间轴 | 合成轴表示日期，精确观测时间通过来源表查询；每天一层不表示所有像元在同一时刻采集 |

允许跨轨日合成会提高可用覆盖，但不同日期、位置可能选中不同轨道。需要固定观测几何的研究，应使用单轨读取或按轨道分别日合成；选择策略与来源索引让这种变化可以检查。

实现后应增加同日两景互补覆盖、云影冲突、重叠区域选景、同采集重处理去重、各波段来源一致、输入顺序无关、UTC 日边界和来源时间恢复的验收。当前仍是设计说明，Resolver 尚未实现或通过这些日合成测试。
