# 实现审计与优化记录

**What this repo does:** LandSat_GRiTS 将 Landsat Collection 2 产品投影到固定 MGRS extent，按传感器与产品级别保存为 `(time,bands,x,y)` Zarr。它提供目录规划、像元读取、格网化写入、续传、结构核验和 Python 读取。评估负载为**单机、本地文件系统、每产品库单写入者、多年多 tile 按景归档**；不按全球分布式服务评估。

审计日期：2026-10-21（Asia/Shanghai）。本次采用 ponytail 的“先确认具体问题，再做最小完整修复”原则。审计技能本身只出报告；代码修复和优化来自本次任务的明确要求。

## 当前功能与边界

| 能力 | 当前实现 | 验证范围／限制 |
|---|---|---|
| 卫星与产品 | MSS L1、TM L1/L2、ETM+ L1/L2、OLI/TIRS L1/L2，共 7 个产品配置 | Landsat 1–5、7–9；Landsat 6 无影像；不包含 RBV 等历史产品线 |
| 原生 L1 波段 | MSS 4、TM 7、ETM+ 9、OLI/TIRS 11 个光谱数据通道，QA 独立保存 | OLI-only/TIRS-only 按实际采集仪器标记缺失；不将 L2 当作完整 L1 |
| 固定 MGRS 格网 | 冻结 UTM CRS、extent、Affine、像元中心坐标和源表摘要 | 源表 19,002 行；31 个跨日期变更线几何当前明确拒绝 |
| 多分辨率 | MSS 60 m；现代 L1 主格网 30 m；全色独立 15 m | 使用交付产品像元间距，热探测器原始分辨率并非 30 m |
| Zarr 存储 | 格式 2，Blosc/Zstd，无损保存整数值，独立 valid/present | 现有 MSS/L2 与现代 L1 合同保持兼容；没有迁移为 Zarr 3 分片 |
| PC 数据访问 | MSS L1、现代 L2；运行时取得临时签名，COG 窗口读取 | 真实小窗口验证；不等于整 tile 或全历史验收 |
| USGS 数据访问 | 免费 STAC、已解包本地产品、显式 AWS Requester Pays | 本地 TM/ETM+/OLI 全链路测试；真实付费像元访问未验证 |
| 恢复与续传 | 场景提交记录、文件锁、未提交尾部恢复、重复场景跳过 | 不支持历史插入；不保证硬盘损坏或任意文件丢失后的恢复 |
| `verify` | 核对格网／数组结构、时间、场景、来源指纹及压缩配置 | 不逐块校验所有像元，也不证明上游目录没有漏景 |
| 读取 | xarray/Dask；L2 六公共反射率波段视图 | 读取期间停止对应库写入；不做去云、合成或光谱一致化 |
| 工程状态 | Python 包、锁定依赖、CLI、自动测试、构建配置 | 本地仓库尚无提交历史／远程；未配置 CI；不代表已发布服务 |

检查了 `src/landsat_grits` 全部业务模块、入口、配置、项目依赖声明、测试和真实读取诊断脚本。没有把 `.venv`、构建产物或第三方依赖源码全部作为供应链审计对象。

## Must fix：已确认的正确性与安全问题

1. **恢复可能把多景已写数据当成未提交尾部。**  
   **用途：** `SceneStore._open` 根据提交记录恢复数组长度。  
   **问题：** 已写入两景后将 ledger 截成空列表，原实现会将两景全部截去；扩容中途异常也不在即时回滚范围。  
   **修复：** 在任何截断前检查 ledger 类型、字段、唯一身份、UTC 时间顺序及所有数组长度；最多允许一景未提交尾部，超出即拒绝修改。扩容纳入事务异常处理。  
   **不修的后果：** 损坏的提交记录可能触发进一步的数据删除。回归测试验证拒绝后原像元仍在。单景 ledger 丢失与单景崩溃尾部仍不能单凭长度区分，提交记录必须随档案保留。

2. **部分科学元数据被修改后，续传仍会接受。**  
   **用途：** `_open` 检查已有档案是否满足格网和数组约定。  
   **问题：** 修改 valid 类型／填充值、空间 chunks、CRS、Affine 或时间单位后，原实现仍可返回“已提交，跳过”。  
   **修复：** 补查这些字段及根合同、组内波段定义；保留原合同哈希和数据格式。  
   **不修的后果：** 相同整数可能被错误地解释为空间位置、时间或有效掩膜。

3. **合法 Landsat 9 场景可能在目录过滤阶段消失。**  
   **用途：** `catalog.search_items` 在试点数量限制之前筛选仪器。  
   **问题：** `OLI-2/TIRS-2` 别名或缺少 instruments、但完整产品 ID 可识别的场景被过滤成零景。  
   **修复：** 复用已有仪器识别规则，统一别名、完整 C2 ID 回退及矛盾检查；无法可靠识别时明确报错。  
   **不修的后果：** 目录请求虽然成功，最终冻结的清单却可能漏景。

4. **直接调用写入 API 或栅格读取异常可能留下临时凭据。**  
   **用途：** provenance 保存原始来源；读取异常用于排障。  
   **问题：** 直接 `append` 带 SAS／token 的嵌套 STAC 会原样写入来源文件；Rasterio 异常可能把签名 URL 带到 CLI 输出。  
   **修复：** 在 provenance 持久化边界递归去除认证字段；远程栅格异常只报告不含临时 URL 的错误，业务校验错误继续保留。  
   **不修的后果：** 临时访问凭据进入长期档案或运行日志。源对象不被就地修改。

5. **GDAL 虚拟路径可绕过显式访问模式。**  
   **用途：** `access` 限制 USGS 像元必须选择本地或 AWS 访问方式。  
   **问题：** 原实现会放行 `/vsis3/...` 形式的路径，使底层 GDAL 有机会使用环境凭据发出请求。  
   **修复：** 拒绝从输入资产传入 `/vsi...` 路径，继续使用受控的普通本地路径／HTTP／S3 分支。  
   **不修的后果：** 下载行为可能超出配置声明的访问方式。

6. **两个规划进程可能覆盖同一冻结清单。**  
   **用途：** CLI `plan` 承诺不覆盖已有 manifest。  
   **问题：** 两个进程同时完成“文件不存在”检查后，各自搜索，再原子替换同一个文件；后完成者覆盖前者。  
   **修复：** 文件锁覆盖存在性检查、搜索与发布全过程。  
   **不修的后果：** 清单身份及其对应的生产任务不再稳定。并发回归验证第二个规划被拒绝。

## Should fix：可靠性、测试与明显开销

7. **正文读取中断没有重试，签名服务返回过期地址也会被接受。**  
   **用途：** STAC、MTL 和签名接口均依赖 HTTP。  
   **问题：** HTTPAdapter 的重试不能覆盖已返回响应头后的正文截断；原签名函数没有检查有效期。  
   **修复：** 正文截断／正文超时最多尝试三次；无效 JSON 与明确的 HTTP 拒绝不盲目重试。签名检查来源一致性和有效期，过期时刷新一次；最多缓存 256 个仍有效的签名，临期重新取得。  
   **不修的后果：** 短暂传输问题会中止任务，过期签名导致后续像元读取失败。签名缓存只在内存中，不缓存栅格内容。

8. **本地产品目录每景扫描一次，且源文件变化需要在提交前发现。**  
   **用途：** 用完整原始文件名匹配下载并解包的产品。  
   **问题：** N 景、F 个源文件产生约 N 次全树扫描；若只在整个作业退出时发现源文件变化，相关景可能已提交。  
   **修复：** 每次 `run` 懒建一次本地索引，结束后丢弃；读取边界和场景提交前检查本地源文件状态，作业结束检查已枚举目录。成功回执在这些检查通过后生成。  
   **不修的后果：** 大源目录增加重复 I/O，读取中的文件变化可能留下不一致场景。源目录应在任务期间保持只读，输出必须放在源目录之外；stat 检查不是源文件内容哈希。

9. **每个窗口重复打开相同 Zarr 数组元数据。**  
   **用途：** `_write_band` 按固定窗口写入 data 和 valid。  
   **问题：** 每个窗口重新访问组内数组；同一 `(time,bands)` 元数据 chunk 又逐波段反复改写。  
   **修复：** 每个波段复用 data/valid 句柄，同组 scale、offset、source_band、source_dtype、present 各写一行。  
   **不修的后果：** 小窗口和多年归档产生额外文件访问及压缩操作。像元顺序、QA 零值、缺失变量和合同保持不变。

10. **旧真实读取诊断脚本不再匹配写入 API。**  
    **用途：** `tooling/diagnostics/20261020/live_probe.py` 执行两景真实小窗口验收。  
    **问题：** 子类 `_write_band` 未接受新增的 `grid` 关键字，升级后调用会报错。  
    **修复：** 接受并传递组格网；保留历史报告，新运行另存证据。补充 TM、ETM+、OLI 的真实本地 CLI 全链路测试。  
    **不修的后果：** 仅依靠旧报告会漏掉诊断工具已经无法重跑的事实。

## Nice to have：已完成的小改进

11. **同一 tile 重复读取相同分辨率的格网。**  
    **用途：** `plan` 为各产品冻结格网。  
    **问题：** 默认四个 L1 产品重复读表／计算格网六次，实际只有三种分辨率。  
    **修复：** 仅在本次 tile 规划内按分辨率复用；默认由六次降为三次。新清单同时给出 data/valid chunk 数量上限。  
    **不修的后果：** 增加少量规划开销；实测约 0.1 秒／tile，并非主要下载瓶颈，不引入长期全局格网缓存。

12. **Affine 文档将像元边界误写为中心。**  
    **用途：** `GridSpec` 文档说明坐标约定。  
    **问题：** 实际 50RKV 30 m 的 `transform.c=199950`，而 `x[0]=199965`，两者不是同一个位置。  
    **修复：** 明确 transform 描述边界，x/y 描述像元中心；代码无需改变。  
    **不修的后果：** 调用者照错误说明导出栅格时可能引入半像元偏移。

## Zarr 设计结论

继续采用 **Zarr v2＋传感器／产品分组＋每组独立格网＋单景时间 chunk**。时间 chunk 为 1 是当前场景级恢复机制的前提；15 m pan 独立保存，不为压缩目录数量而改变分辨率。当前优化针对实测的重复元数据打开和反复修改相同 chunk，不引入对象存储事务或分布式调度。

默认 512 像素空间 chunk 下，50RKV 完整覆盖一景的 data＋valid 块数上限为：

| 产品 | 块数上限／景 |
|---|---:|
| `mss-l1` | 192 |
| `tm-l1` | 1,152 |
| `etm-l1` | 1,730 |
| `oli-l1` | 1,986 |

这些不是实际文件数：全填充值块可省略，表内不含坐标、提交记录和来源文件。1,000 景 OLI 的上限接近 199 万个像元块，应在扩大规模前按目标磁盘和读取方式测量。新清单的 `estimated_data_and_valid_chunks_upper_bound` 用于提前评估该负担。

Zarr 3 分片可作为后续独立格式实验，但会影响兼容性、恢复和读取验证。本次没有证据支持直接迁移现有档案，也没有承诺某个 chunk 大小适合所有负载。[Zarr 官方性能说明](https://zarr.readthedocs.io/en/stable/user-guide/performance/)

局部基准的确定性操作计数如下，三次运行计数相同：

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 波段窗口中的 data/valid 数组元数据打开次数 | 774 | 12 |
| scale/offset/source_band/source_dtype/present 写入次数 | 30 | 10 |
| VRT 读取次数 | 768 | 768 |
| 三次耗时中位数 | 1.568 秒 | 1.512 秒 |

耗时仅作示例。前后基准具有相同数组大小、通道数、chunk 和计数范围，但前次命令及像元分布没有保留；压缩性、操作系统缓存和并发工作也影响耗时。后值记录的代码版本早于最后增加的 ledger 格式校验，不能把它当成最终版本的严格性能验收。可核对[基准前值](evidence/audit-20261021-storage-before.json)和[基准后值](evidence/audit-20261021-storage-after.json)中的版本摘要。

## 下载设计结论

保持“先冻结目录，再按目标窗口读取”的两步流程。PC 继续签名访问，USGS L1 继续采用本地产品导入或明确配置的 Requester Pays。网络重试有上限，目录分页失败不会生成看似完整的清单；本地文件索引只在一个作业内复用。

窗口读取仍可能传输整个源压缩块，不能将输出数组大小当作网络下载量。当前没有自动 EarthExplorer/M2M 登录下载、跨任务栅格缓存、全景预下载缓存或带宽调度；本次也没有执行收费读取。[GDAL 远程文件访问说明](https://gdal.org/en/stable/user/virtual_file_systems.html)、[Rasterio 虚拟重投影](https://rasterio.readthedocs.io/en/stable/topics/virtual-warping.html)
